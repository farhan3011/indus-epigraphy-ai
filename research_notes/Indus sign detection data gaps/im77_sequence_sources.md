# Machine-readable Indus inscription sequences in Mahadevan (IM77, 417-sign) numbering — sources as of 1 Oct 2026

Method note: every "verified" item below was opened and inspected directly on 1 Oct 2026 (files downloaded with curl, counts recomputed locally in Python). Items marked "not opened" could not be accessed.

## 1. What does indusscript.in (RMRL / Indus Research Centre "Indus Script IM77") expose?

### Takeaway
indusscript.in is a Flutter single-page web app backed by Google Firebase/Firestore, gated behind Google sign-in; it has no static text listing, no documented API, no bulk download and no robots.txt or visible terms. It does hold the complete IM77/IDF80 corpus (3,916 records, 2,906 text numbers), and two third parties have already exported it to CSV on GitHub (section 4), so scraping it yourself is unnecessary.

### Cited Findings
- The homepage is a 3.5 KB HTML shell (title "The Indus Script(IM77)", meta description "by Iravatham Mahadevan", last-modified 30 Sep 2021) that loads `main.dart.js` (3.55 MB Flutter web bundle) plus Firebase app/auth/firestore/analytics 8.6.1; Firebase project id `theindusscript`; a Google sign-in client id is embedded. No content is server-rendered, so plain HTTP fetch/WebFetch returns only the title. — [indusscript.in](https://indusscript.in/)
- `https://indusscript.in/robots.txt` returns HTTP 200 with the same SPA HTML shell (Firebase Hosting catch-all rewrite), i.e. there is no robots.txt file and no crawl directives. — [indusscript.in/robots.txt](https://indusscript.in/robots.txt)
- UI strings present in the app bundle: "Texts, Concordance and Tables (IM77/IDF80)", "Texts:", "Field Symbol" / "Field Symbol Type" / "Field Symbol Description", "Pairs", "Frequency of Pairs", "Triplets", "Frequency of Triplets", "Pairing", "Download results of current query as a PDF", "Login again, or try from a different device". So the app offers search over texts, field symbols, sign pairs and sign triplets, with per-query PDF export only (no CSV/JSON export). — [indusscript.in/main.dart.js](https://indusscript.in/main.dart.js)
- A third-party export note (dated 23 Sept 2026) describes the site as "run by the Roja Muthiah Research Library", says the data was "exported from the site's own database while signed in", that texts are identified by Mahadevan text number 1001–9905, that the site offers pair and triplet tables (2,730 sign pairs), that sign drawings are served at `https://indusscript.in/assets/images/<sign>.png` (0–417), and that the link to Mahadevan's introduction PDF on the site is dead. — [paragorth/Indus- IM77_README.md](https://github.com/paragorth/Indus-/blob/claude/indus-script-dictionary-u3dzf8/data/im77/IM77_README.md)
- A second independent export describes the backend as Firestore, "obtained via a logged-in browser session and JavaScript extraction", with raw record fields `textnum`, `sideline`, `posnum`, `dir`; 3,916 total records, 343 with posnum=0, 3,573 non-empty line records, 2,906 distinct textnums, 14,153 sign occurrences, 504 starred (doubtful) occurrences. Its corpus registry classifies access as "authenticated, not public bulk". — [joyboseroy/indus_decipher convert_m77_indusscript_to_csv.py](https://github.com/joyboseroy/indus_decipher/blob/main/data/convert_m77_indusscript_to_csv.py); [CORPUS_REGISTRY.md](https://github.com/joyboseroy/indus_decipher/blob/main/CORPUS_REGISTRY.md)
- Text-number ranges encode site and publication: 1001–1905 Mohenjodaro (MIC vol III); 2002–2952 Mohenjodaro (FEM vol II); 3001–3513 Mohenjodaro other; 4001–4905 Harappa (EH vol II); 5001–5601 Harappa other; 6104–6306 Chanhudaro (CE); 6402–6405 Chanhudaro other; 7001–7301 Lothal; 8001–8302 Kalibangan; 9001–9701 other sites; 9801–9905 West Asian finds. — [IM77_README.md](https://github.com/paragorth/Indus-/blob/claude/indus-script-dictionary-u3dzf8/data/im77/IM77_README.md)
- Mahadevan 1977 (M77) "records 417 unique signs in 3573 lines of 2906 texts". — [Yadav et al. 2010, PLoS ONE](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0009506)

### Inferences
- The 3,916 records = 3,573 text lines + 343 "field symbol but no text" placeholder records (line code 9 / posnum 0); the 3,573 and 2,906 figures match Mahadevan 1977 exactly, so the site holds the full concordance, not a subset.
- Scraping is technically possible only through an authenticated browser session reading Firestore (not by HTTP crawling). It is not needed: the two GitHub exports in section 4 already contain the whole corpus.
- Licence/terms in one line: no terms of use, licence or copyright statement was found on the site shell, manifest, or in the string search of the app bundle; treat the data as Mahadevan/RMRL work with no explicit open licence.

### Gaps
- I did not sign in, so the live UI (exact screens, whether photographs are shown, any in-app terms/about text) was not seen; the feature list is inferred from bundle strings and third-party notes.
- Whether Firestore security rules permit unauthenticated REST reads was deliberately not probed.
- No statement from RMRL on reuse/redistribution was found. The SoylentAquamarine/indus-script-collective repo contains a file named `logs/2026-09-29-rmrl-request-draft.md` (a drafted permission request to RMRL), which I did not read. — [SoylentAquamarine/indus-script-collective](https://github.com/SoylentAquamarine/indus-script-collective)

## 2. What does Hugging Face `hellosindh/indus-script-synthetic` contain?

### Takeaway
It is 5,000 purely synthetic NanoGPT-generated sequences in an unexplained "T###" numbering (IDs up to T813, 641 attested signs) that is NOT Mahadevan numbering; the 3,310 real training inscriptions are not included. It is not usable as a source of real IM77 sequences.

### Cited Findings
- Actual repo files (the card's file table is out of date): `synthetic_indus_5k.csv` and `reference/sign_index.json`; the card lists `synthetic_indus_5k.jsonl` and `sign_index.json`, and those paths return "Entry not found". Created 10 Apr 2026, last modified 10 Apr 2026, 29 downloads, 0 likes. — [HF API](https://huggingface.co/api/datasets/hellosindh/indus-script-synthetic); [dataset page](https://huggingface.co/datasets/hellosindh/indus-script-synthetic)
- CSV: 5,000 rows; columns `id, sequence, sequence_str, glyphs, length, bert_score, ngram_score, electra_score, ensemble_score, source`. Example: `syn_00000, "638 650 100 100", "T638 T650 T100 T100", <PUA glyphs>, 4, 0.9815, 0.8537, 0.9099, 0.9317, synthetic_nanogpt`. Every row has `source = synthetic_nanogpt`; 170 distinct sign IDs are used. No site, object type, direction, line or damage metadata. — [synthetic_indus_5k.csv](https://huggingface.co/datasets/hellosindh/indus-script-synthetic/blob/main/synthetic_indus_5k.csv)
- `reference/sign_index.json`: keys `description, total_signs (715), sign_id_format, roles, signs`; 715 sign entries of which 641 have corpus_count > 0, summing to 13,427 tokens; highest ID is T813. Per-sign fields: `sign_id, glyph (private-use Unicode codepoint), corpus_count, corpus_freq_pct, role (PREFIX/SUFFIX/CORE/RARE/UNSEEN), start_rate_pct, end_rate_pct`. Top entries: T638 count 1,372 (10.22%, start rate 28.55%); T101 count 605 (4.51%). — [sign_index.json](https://huggingface.co/datasets/hellosindh/indus-script-synthetic/blob/main/reference/sign_index.json)
- Card: trained on "3,310 real archaeological inscriptions" (source not named); real sequences were used for training only; 752 generated sequences that exactly matched real inscriptions were "separated as seal reproductions" and are not in the file; average synthetic length 7.53 vs ~4.5 real; only ~168 of 641 sign types appear; the card itself says the set is unsuitable for "token frequency or vocabulary distribution studies" and "full realistic simulation of Indus inscriptions". Models at hellosindh/indus-script-models. — [dataset card](https://huggingface.co/datasets/hellosindh/indus-script-synthetic)
- Licence in one line: CC-BY-4.0 (card metadata). — [dataset card](https://huggingface.co/datasets/hellosindh/indus-script-synthetic)

### Inferences
- A sign inventory of 641 attested / IDs up to 813 cannot be Mahadevan's 1–417 list; it resembles the larger Wells/Fuls-type lists (ICIT uses a 700+ sign list). The card does not state the scheme, and no T-number to Mahadevan mapping is supplied.
- T638 (10.2% of tokens, strongly positional) behaves like Mahadevan 342 (jar; 10.4% of IM77 tokens), and T101 (4.5%) like Mahadevan 99 (4.9%), but this is a statistical resemblance, not a documented mapping. Note the order convention differs: T638 has a 28.55% start rate and 0.15% end rate, whereas 342 is the reading-order closer in the IM77 exports, so the HF sequences are stored in the opposite (physical left-to-right / reversed) order. Do not mix the two files without reversing one.
- For the student project it offers at most a cross-check of positional statistics, not sampling material.

### Gaps
- The numbering scheme and the source of the 3,310 real inscriptions are undocumented; I did not open the companion model repo to look for a vocabulary file.

## 3. What is the "AI-Epigraphy" toolkit on GitHub?

### Takeaway
AI-EPIGRAPHY is a single-file Tkinter application (IndiaHCI '25 paper) at github.com/atulsharma0071/indiahci2025; its bundled data is a 44-row table of the authors' own letter-coded "readings", with no Mahadevan numbers and no real corpus. It is of no use as a sequence source.

### Cited Findings
- Repo: `atulsharma0071/indiahci2025`, description "AI-EPIGRAPHY: An Interactive Tool for Computational Decipherment of the Indus Valley Script"; created 10 Oct 2025, last push 2 Mar 2026, 1 star; exactly three files: `README.md`, `hciup.py` (68 KB), `indus - symbols.csv` (4.5 KB). — [GitHub repo](https://github.com/atulsharma0071/indiahci2025)
- Paper: Atul Sharma and Shubhajit Roy Chowdhury, "AI-EPIGRAPHY: An Interactive Tool for Computational Decipherment of the Indus Valley Script", IndiaHCI '25, ACM, pp. 69–74, doi 10.1145/3768633.3770145; describes a Model-View-Controller architecture using Tkinter, pandas, NumPy, scikit-learn, Matplotlib, NetworkX. — [ACM DL](https://dl.acm.org/doi/10.1145/3768633.3770145)
- `indus - symbols.csv`: 45 lines (header + 44 rows); columns `No., Inscription, Reading, Meaning/Interpretation, Site, Source`. Inscriptions are written as Latin-letter codes joined by arrows (e.g. `UF→O`, `UF→W→R→O`) with speculative phonetic readings ("Pa-ba-ha-a") and meanings ("Protector ..."); sources cite Vats plate numbers (Harappa). Several rows have visibly misaligned/garbled columns. — [indus - symbols.csv](https://github.com/atulsharma0071/indiahci2025/blob/main/indus%20-%20symbols.csv)
- Licence in one line: none declared (GitHub API `license: null`), i.e. all rights reserved by default. — [GitHub repo](https://github.com/atulsharma0071/indiahci2025)

### Inferences
- The tool is a generic n-gram/clustering GUI that expects the user to supply a dataset; it bundles neither IM77 nor any standard numbering.

### Gaps
- The ACM paper full text was not opened (search snippet only).

## 4. Other digitisations: which are actually downloadable?

### Takeaway
The full IM77 corpus in Mahadevan numbering is downloadable today from two recent GitHub repos that exported indusscript.in: `paragorth/Indus-` (best: full metadata) and `joyboseroy/indus_decipher` (sequences only). EBUDS itself is not published anywhere, but applying its published filter to the paragorth CSV reproduces it exactly (1,548 texts / 7,000 tokens / 377 signs). ICIT (Fuls/Wells) is login-only and uses a different sign list; yajnadevam/indus-website is downloadable but in ICIT-style glyph IDs.

#### 4c. EBUDS (Yadav, Vahia, Mahadevan, Joglekar; used in Rao et al. 2009)

### Inferences
- For the student project the practical source is paragorth's `im77_corpus_lines.csv` (sequences + site, object type, side, line, direction, field symbol, damage and doubt markers), cross-checked against joyboseroy's independent export. Both are weeks old, single-author, AI-assisted repos with 0 stars; their agreement with each other and with published M77/EBUDS totals (2,906 / 3,573 / 13,372 / 1,548 / 7,000 / 377) is the main evidence of fidelity.
- Because the file is in reading order (opener first; jar sign 342 last), rendering a right-to-left seal impression means placing the first sign at the right edge; `direction` gives the per-line exception cases, and seals (as opposed to impressions) are carved mirror-reversed.
- Multi-line objects can be reassembled by grouping on `text_no` and ordering by `side`, `line`; for n-gram work, treat each row as a separate sequence and treat `0` as a break.
- The exact EBUDS match means published EBUDS n-gram results (Yadav 2010, Rao 2009) can be used as regression tests for any n-gram code written on this file.
- Redistribution status is the weak point: both exports came from a signed-in session on a site with no stated licence; the MIT labels cover the repos' code/derived tables, not necessarily Mahadevan/RMRL's underlying data.

- ICIT content could not be inspected (401); current text/sign counts are from secondary pages and differ between sources.

## 5. Published sign-frequency and positional statistics for the Mahadevan sign list

### Takeaway
A full per-sign frequency table for all 417 signs is downloadable (`im77_sign_frequencies.csv`) and matches the corpus: sign 342 (jar) has 1,395 of 13,372 tokens (10.4%), followed by 99, 59, 267, 87, 176, 328, 89, 67. The distribution is strongly Zipfian (about 69 signs cover 80% of EBUDS), and positional skew is extreme (342 ends 703 of the clean single-line texts).

### Inferences
- The brief's example "342, 99, 267" is right; note 59 (381) narrowly outranks 267 (376) in the full corpus while Yadav et al. order them 99, 267, 59 on EBUDS.
- For synthetic seal generation, sampling whole real lines from the corpus (optionally filtered to `object_type = seal`, no `0`) preserves frequency, length and positional structure automatically; unigram-weighted sampling alone would misplace 342 (terminal) and 267 (initial).
- The Kaggle IM-417-150 set covers all 417 Mahadevan classes, so every sign in these sequences should have glyph images; the 112 hapax signs will be the thin classes. (Coverage of that dataset was not checked here.)
